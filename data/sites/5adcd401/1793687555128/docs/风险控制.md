# 风险控制

入口：系统管理 → 风险控制。只有具备系统管理权限的管理员可以查看和修改。

保存弹窗、详情页和本列表读的是同一个 `dashboard.risk_level`。写入口只有这里。保存弹窗只读取并回传当前值，新建时由服务端落成 1 级。

本页同时回答两件事：每张看板现在是几级，以及这个等级下下载要不要审批。

## 页面结构

| 区域 | 规则 |
| --- | --- |
| 标题 | 「风险控制」+「共 N 个仪表板」。说明「等级由业务保存时自定，管理员可在此统一修正」。 |
| 等级概览 | 1–4 级四张卡，展示数量和级别名。点击按该等级筛选，再点一次取消。数字与流程配置里的管控范围同源。 |
| 筛选 | 名称模糊搜索（回车即查）+ 风险等级 + 标签多选 + 查询 / 重置。条件靠左，查询和重置靠右。标签之间为「或」，与名称、等级为「与」。重置清空三项。 |
| 列表列 | 名称、所在目录、标签（最多 3 个，超出 `+N`）、风险等级、下载审批、最近修改。 |

## 改级

- 等级列是胶囊内下拉，直接选 1–4 级。选中即提交，成功后配色和「下载审批」一起刷新，toast「已改为 n 级 · 级别名」。
- 新级别低于原级别时必须确认，写明「从 x 级降为 y 级」。降为 1 级时补充「下载将不再需要审批」。取消则回滚，不落库。
- 接口再校验 `ackDowngrade`，防止绕过前端。

## 批量改级

- 行首可勾选。表头全选只作用于当前筛选结果。切换筛选或搜索即清空已选。
- 批量条常驻：左侧「已选 N 项」，右侧「批量设为」+ 目标等级 + 应用。
- 未勾选时仍可先选目标等级，但「应用」置灰。
- 含降级时合并成一次确认，写明 N 个里有几个是降级。未带 `ackDowngrade=true` 时整批拒绝。纯升级直接生效。
- 单次最多 200 个。无权限或已删除的跳过，其余生效，提示「成功 N 个，跳过 M 个」，并保留失败行的勾选。

## 下载审批列

只有「免审批」和「需审批」，不展示命中的流程条数。该级别命中任一启用流程（门槛 ≤ 该级别）即为「需审批」。门槛最低为 2 级时，实际是 1 级免审批，2–4 级需审批。

每次改级写入资产变更记录（旧值、新值、操作人、时间）。审批记录里的 `resource_risk_level` 是提交时快照，不随后来的改级回溯。

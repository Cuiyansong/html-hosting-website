仪表板标签

在现有 BI 产品的仪表板上引入「标签」这一轻量元数据能力：由系统管理员统一维护标签字典， 业务用户在保存仪表板时为其打上若干标签，从而支撑仪表板的归类、检索与治理。

另：仪表板保存时新增「风险级别」（默认 1 级，只读展示，改级走「系统管理 → 风险控制」）； 下载审批按「资源级别 ≥ 门槛」判定，门槛现状为 ≥2 级，详见第 10 章。

01需求背景与目标

当前仪表板仅通过「目录 / 文件夹」做单一层级的归置，一个仪表板只能落在一个目录下。 但业务方的实际诉求是多维归类：同一张经营分析看板，既属于「财务」主题，也服务于「经营分析」主题。 目录无法表达这种多归属关系，导致：

  • 仪表板资产量大后，用户只能靠名称搜索，找不到「某个主题下都有哪些看板」；
  • 数据治理时无法按业务主题盘点资产，资产地图缺失；
  • 新增看板时无法快速复用同主题的历史看板，重复建设。

本需求引入「标签」，作为与目录并行的第二套归类维度：目录解决「放在哪里」（唯一归属、有层级）， 标签解决「是什么主题」（多归属、扁平、可交叉）。

02名词定义与设计取舍

术语定义
标签用于标识仪表板所属业务主题（如财务、供应链、人力）的扁平化元数据，全局唯一，由管理员统一维护。
标签字典系统管理模块中维护的全部标签集合，是打标时的可选范围来源。用户不可在打标时随意创建"私有标签"以外的字典项。
绑定关系仪表板与标签的多对多关联记录。一个仪表板可绑定多个标签，一个标签可被多个仪表板绑定。
关联数某标签当前被多少个仪表板绑定，用于删除前的风险提示。

为什么用"多对多"而不是"单选标签"

若做成单选，用户必须为看板强行指定唯一主题，跨主题看板会被迫二选一，长期必然出现"选哪个都别扭"的问题，且后期改造成本高。 多对多虽增加了一次选择的复杂度，但通过数量上限（10 个）+ 已选计数 + 可搜索选择即可控制，收益远大于成本。

03整体流程

1
管理员配置标签字典 系统管理 → 仪表板标签：新建、编辑、删除标签，维护全局可选范围。
2
用户在保存时打标 新建/编辑仪表板 → 保存弹窗 → 风险级别（只读展示，新建默认 1 级）+ 标签（多选，可内联新建）。
3
标签在消费侧生效 仪表板列表展示标签、按标签筛选；详情页展示并可随时修改。

05功能详述

5.1 系统管理 · 仪表板标签（列表页）

入口：系统管理 → 仪表板标签。左侧导航中「系统管理」为二级菜单，「仪表板标签」与用户管理、角色权限并列。

区域内容与规则
页面标题区标题「仪表板标签」+ 一句话说明「统一维护仪表板的标签，供保存仪表板时选择」；右侧主按钮「新建标签」。
筛选区标签名称输入框（占位「请输入标签名称」）+「查询」「重置」；输入框支持回车查询。名称搜索为 contains 模糊匹配，忽略首尾空格。
列表列标签名称（主字段，加粗）｜关联仪表板（数字，可点击跳转到已筛选的仪表板列表）｜创建人｜创建时间｜更新时间｜操作。
操作列「编辑」「删除」两个文字按钮，固定右侧。删除为危险色。
排序默认按更新时间倒序；新建/编辑成功后该行回到首位并高亮 1.5s。
分页默认 20 条/页，展示总数；数据不足 1 页时仍展示总数文案，隐藏翻页按钮。
空状态无任何标签时展示插画 +「还没有标签」+「新建第一个标签」按钮；搜索无结果时展示「未找到匹配的标签」+「清空筛选」。

5.2 新建标签

点击「新建标签」弹出居中弹窗，宽度 440px，仅一个表单项。

  • 标签名称（必填）：单行输入框，maxlength = 20，右下角实时显示 n/20 计数。
  • 校验时机：输入时只做长度截断；失焦与提交时做唯一性校验，错误内联展示在输入框下方，不弹 toast。
  • 提交中按钮进入 loading 且禁用，防止重复提交；成功后关闭弹窗、toast「标签创建成功」、列表刷新。
  • 按 Esc 或点击遮罩关闭；若已输入内容，关闭前不做拦截（轻量表单，避免过度打扰）。

唯一性规则：全租户内标签名称唯一，比较时忽略首尾空格且不区分大小写（"财务"与"财务 "视为重复；"Finance"与"finance"视为重复）。

5.3 编辑标签

弹窗结构同新建，标题为「编辑标签」，名称预填当前值。顶部展示影响提示：「修改名称后，已关联的 N 个仪表板将同步展示新名称。」

保存时若名称未发生变化，则不发请求直接关闭；若变化，走同一套唯一性校验（排除自身 ID）。

5.4 删除标签

场景弹窗文案与交互
关联数为 0标题「删除标签」；正文「删除后不可恢复，确定删除标签「{name}」吗？」；按钮「取消 / 删除」。
关联数 > 0标题「删除标签」；正文「标签「{name}」已被 N 个仪表板使用，删除后这些仪表板将不再展示该标签，仪表板内容不受影响。」；按钮「取消 / 删除」。正文以警示色强调数量。

删除为软删除（记录标记 deleted=1），绑定关系同步失效。删除成功后列表移除该行、toast 提示，分页自动回退（当前页为空时跳转上一页）。

5.5 保存仪表板：风险级别与标签

在仪表板编辑态点击「保存」后弹出的保存弹窗中，新增「标签」配置区（非必填）。 编辑已有仪表板时，弹窗需回显该仪表板当前已绑定的标签。

本期在同一弹窗新增「风险级别」，位于「保存位置」之后、「标签」之前。它是仪表板自身的资源级别： 下载审批时与流程门槛比较（资源级别 ≥ 门槛才需要审批），与标签互不影响。 该字段在此处只读展示、不可修改——定级是治理动作，改级收敛到「系统管理 → 风险控制」，避免业务在保存时顺手把级别调低来绕开审批。

元素规则
控件形态只读展示：浅灰只读容器内一枚等级徽标（形如「2 级 · 内部」）+ 锁图标与一句「改级请到「系统管理 → 风险控制」」。整块不可点、无 hover、无下拉，光标离开是普通箭头而非手型，视觉上就能看出「这不是让你选的」。
默认值新建保存固定为 1 级 · 公开，随仪表板落库；弹窗内不提供修改入口。默认取最低级别：新建看板多数是公开或内部数据，若默认最高级，"没细想"会直接变成"全量审批"。
影响提示徽标下方一句话说明后果：「下载时将命中 k 条启用流程（门槛 ≤n 级）」，k 为 0 时改为「按当前生效的流程，下载无需审批」。数字取分级统计接口，不写死。
编辑回显编辑已有仪表板（含只改名称）时回显当前级别，同样只读；存量未定级的仪表板展示 1 级并标注"原来未定级，按 4 级受控"（存量处置见 Q-08）。
提交随仪表板、标签同一次请求提交（riskLevel 回传当前值：新建 1 级、编辑原值），不单独开接口，避免"级别存了、仪表板没存"。
唯一改级入口「系统管理 → 风险控制」列表内改级（需管理员权限，见 5.7）；保存弹窗只展示，形成"业务打标、管理员定级"的单一口径。
展示位详情页标题后展示级别徽标，形如 2 级 · 内部——不带 ≥：资源侧表示自身级别，流程侧 ≥3 级 才是门槛，两种符号不得混用。

标签配置区（非必填，最多 10 个）：

元素规则
选择方式标签以可点击的 chip 平铺展示，点击切换选中；已选 chip 为品牌色描边+浅底+勾选图标。
已选计数区域右上角展示「已选 n/10」，n 随点击实时变化；达上限后未选中的 chip 置灰不可点，并 toast「最多选择 10 个标签」。
内联新建标签标题行右侧提供「＋ 新建标签」；点击在 chip 列表上方展开一行输入框 +「添加」按钮，添加成功后新标签立即以选中态出现在 chip 列表末尾，无需退出保存流程；同时写入标签字典，「标签管理」中可见（关联仪表板 1 个）。输入框有内容但未点「添加」就点「保存」时，先自动创建再保存，不静默丢弃。
清空已选 > 0 时展示「清空」文字按钮，一键取消全部选中。
字典为空chip 区展示「暂无可用标签，先去创建」文案；标题行「＋ 新建标签」始终可用，仍可直接在本弹窗内创建，不跳出去建标签。
提交与仪表板保存同一次请求提交（标签作为 tagIds[] 字段），避免"标签存了但仪表板没存"的不一致。

5.6 仪表板列表与详情展示

  • 列表列：新增「标签」列，位于「所属目录」之后。最多展示 3 个标签，超出显示 +N，hover 浮层展示全部标签名称。
  • 筛选：筛选区新增「标签」多选下拉，支持搜索与「清空」；多个标签之间为 或 关系（命中任一即展示），结果与目录筛选为 与 关系。
  • 无标签：展示「—」，不占位、不显示"未打标"文案，避免列表噪音。
  • 目录树：左侧目录树顶部固定「仪表板概览」，默认选中，以列表形式展示全部仪表板（含标签列）；点击具体目录后列表按目录过滤，页面标题与数量随之切换，概览项始终置顶。
  • 详情页：标题下方展示全部标签 chip；点右侧「编辑」（或标题旁铅笔）打开与保存完全一致的弹窗，标签可增可减、名称可改，保存后标签行即时回写，无需另设标签入口。
  • 风险级别：详情页标题后展示级别徽标（如 2 级 · 内部），修改入口在「保存」弹窗内；与标签各自独立，互不覆盖。

5.7 系统管理 · 风险控制（列表维护风险等级）

入口：系统管理 → 风险控制，与「仪表板标签」「用户管理」「角色权限」并列。只有具备系统管理权限的管理员可见、可改；业务方仍在自己保存仪表板时定级，两个入口写的是同一个字段。

这一页回答两个问题：每张看板现在是几级，以及这个等级下下载要不要审批。前者是维护对象，后者是维护后果——放在同一行，管理员改完当场就能看到影响，不用切页面推演。

区域内容与规则
页面标题区标题「风险控制」+ 数量「共 N 个仪表板」；右侧一句话说明「等级由业务保存时自定，管理员可在此统一修正」，点明两个入口的从属关系，避免业务以为自己的定级被覆盖。
等级概览四张卡（1–4 级），展示各等级仪表板数量与级别名；点击卡片即按该等级筛选，再点一次取消。数字取分级统计接口，与流程表单里的「管控范围」同源，不各算一套。
筛选区仪表板名称（contains 模糊，回车即查）+ 风险等级下拉（全部 / 1–4 级）+ 标签多选 + 查询 / 重置（条件靠左、查询 / 重置靠右对齐）。标签以折叠面板承载（点击展开复选列表，带各标签的仪表板计数，顶部可「清空」），选中项在按钮上回显为标签名或「已选 N 个标签」。标签之间为「任一命中」（OR），标签与名称 / 等级之间为「与」（AND）；面板点外部自动收起。重置清空三项条件。
列表列仪表板名称（主字段加粗，下方一句话说明）｜所在目录｜标签（最多 3 个，超出 +N）｜风险等级｜下载审批｜最近修改。
行内改等级等级列为可点的胶囊内下拉，直接选 1–4 级。选中即提交单条改级接口，成功后胶囊配色与右侧「下载审批」同步刷新，toast 提示「已改为 n 级 · 级别名」；不进详情、不打断筛选。
多选与批量改级行首勾选框，表头全选只作用于当前筛选结果；切换筛选 / 搜索即清空已选，避免看不见的项被一起改。表格上方常驻批量条，两端分布：左侧「已选 N 项」，右侧「批量设为」+ 目标等级 + 应用；未勾选时批量条仍显示，目标等级可先选，但「应用」置灰不可点（悬停提示「请先勾选需要修改的仪表板」）。取消勾选由行内 / 表头复选框完成，批量条不设「取消选择」。批量中含降级时合并为一次确认（写明 N 个里几个是降级），不逐条弹窗；纯升级直接生效。单次上限 200 个。
下载审批列只有两种状态：「免审批」/「需审批」，不展示命中的流程条数。判定同 10.4：该级别命中任一启用流程（门槛 ≤ 该级别）即「需审批」。因下载流程门槛最低为 2 级，实际呈现为只有 1 级免审批，2–4 级都需审批。
降级确认新级别低于原级别时弹确认：写明「从 x 级降为 y 级」；降为 1 级时补一句「下载将不再需要审批」，降为 2–4 级时提示「仍需审批」。取消则该行下拉回滚到原值，不落库。
权限与审计仅系统管理权限可改；每次变更写资产变更记录（旧值 → 新值、操作人、时间）。审批记录中的 resource_risk_level 是提交时快照，不随这里的修改回溯。

批量为什么带这几条约束：批量改级是「一次放宽几十张看板」的开关，出错只能靠变更记录逐条复原。所以批量条常驻但「应用」随勾选数启用（0 项即置灰）、全选只作用于当前筛选结果、含降级必须确认并写清条数、单次上限 200 条、部分失败逐条回执。这些不是交互装饰，是让批量可控的前提。

BR-01名称唯一标签名称在租户内全局唯一，忽略首尾空格、不区分大小写。
BR-02名称格式1–20 个字符；允许中文、英文字母、数字、下划线、中划线、空格（非首尾）；禁止 / \ : * ? " < > | 等特殊字符与 emoji。
BR-03绑定上限单个仪表板最多绑定 10 个标签，最少 0 个（标签非必填）。
BR-04改名同步标签改名后，所有已绑定仪表板同步展示新名称（通过 tagId 关联，不做名称冗余）。
BR-05删除解绑删除标签时级联解除全部绑定关系；仪表板本身、目录归属、权限均不受影响。
BR-06软删除标签删除为软删除，保留 ID 以防历史操作日志/审计记录断链；已删除标签不可被再次绑定。
BR-07原子提交仪表板保存时，基础信息与标签绑定在同一事务内提交，任一失败则整体回滚。
BR-08权限隔离无「仪表板标签管理」权限的用户，系统管理菜单中不展示该项；无仪表板编辑权限的用户，保存弹窗中标签区只读展示。
BR-09排序稳定列表默认按 update_time DESC 排序，同一秒内按 id DESC 兜底，保证分页稳定。
BR-10租户隔离标签数据按租户隔离，跨租户不可见、不可复用。
BR-11等级同一字段保存弹窗、详情页、风险控制列表读同一个 dashboard.risk_level；写入口只有一个——「风险控制」。保存弹窗只读取回传当前值（新建时由服务端落 1 级），因此不存在两个入口互相覆盖；每次改级产生一条变更记录。
BR-12降级需确认新级别低于原级别视为放宽，必须经二次确认后才提交；接口层再校验一次 ackDowngrade，防止绕过前端直调。批量同理：请求中含任一降级项且未带 ackDowngrade=true 时整批拒绝，不做部分提交。
BR-14批量上限与部分失败单次最多 200 个仪表板；按 id 逐条落库，无权限或已删除的跳过并返回 skipped 列表，其余正常生效，前端提示「成功 N 个，跳过 M 个」并保留失败行勾选，便于重试。
BR-13下载审批两态风险控制列表的「下载审批」只有免审批 / 需审批两种取值，不展示命中的流程条数。取值按 10.4 判定：该级别命中任一启用流程即「需审批」，否则「免审批」。下载流程门槛均 ≥2 级时，结果即1 级免审批、2–4 级需审批；条数属配置侧信息，在流程配置里看。

08边界与异常

场景处理策略
保存仪表板时，所选标签已被他人删除提交前不做实时校验；失败后返回 TAG_NOT_FOUND，弹窗保持打开，自动刷新标签选项并移除失效项，提示用户重新确认后再次保存。
两人同时新建同名标签以数据库唯一索引兜底，后提交方返回 DUP_TAG_NAME，前端内联提示。
标签名称前后有空格提交前 trim；仅空格视为空值，触发必填提示。
已选满 10 个后继续点击未选中的 chip 呈禁用态（cursor:not-allowed、透明度 45%），点击 toast 提示上限。
标签字典为空时保存仪表板标签区不阻塞保存；展示「暂无可用标签，先去创建」并提供内联新建入口。
删除当前页最后一条刷新后若当前页无数据且页码 > 1，自动回退一页。
无标签权限的用户访问打标接口返回 403，前端 toast「暂无权限操作标签」，不暴露标签字典内容。
关联数展示与实际瞬时不一致允许短暂误差；点击关联数跳转时以实时查询结果为准，不以冗余字段作为跳转依据。
两人同时修改同一仪表板等级后提交者覆盖，变更记录留两条（含各自操作人/时间）；先提交者页面在下一次刷新时展示最新值，不做实时互斥锁。
降级时该仪表板有审批中的单据不影响在途单据：审批继续按提交时的 resource_risk_level 快照走完，只有之后的下载按新级别判定。

勾选若干行后修改筛选条件已选清空，批量条收起。跨筛选保留勾选会让「看不见的行」被一起改级，风险高于省一次点击。

10风险级别与审批判定

本章只定义两件事：仪表板的四级口径，以及下载时按什么规则判断「要不要审批」。 级别的维护入口在「系统管理 → 风险控制」（见 5.7），本章不再重复交互细节； 审批流程自身怎么配门槛属于审批配置侧能力，不在本期原型范围（见 10.5）。

与标签功能的关系：两者互不依赖、可分别上线。标签解决「仪表板是什么主题」，风险级别解决「审批流管多敏感的数据」。本文档 1–4 章与 5.1–5.6 讲标签，5.7、第 10 章与第 11 章的 Q-05–Q-09 讲风险级别与等级维护。

10.1 分级口径

参照 GB/T 43697-2024《数据安全技术 数据分类分级规则》的纵向划分：核心数据、重要数据、一般数据， 其中一般数据内部可再细分。BI 平台承载的是企业经营分析数据，绝大多数落在「一般数据」区间， 因此本功能不判定核心 / 重要数据，只把「一般数据」内部再细分为 4 级。 若客户场景确实涉及核心 / 重要数据（如服务国防、能源、大规模高精度地理数据）， 按客户侧定级结论单独约定，不走本功能的四级模型。

级别名称判定口径（泄露后的影响）典型数据（经营 / 营销场景）
1 级公开 / 低敏无影响或影响极微弱，可对外披露。商品公开价格、官网促销图文、公开的用户评价、已对外发布的经营月报。
2 级内部 / 中敏造成轻微竞争劣势，或对个人造成轻微困扰。匿名化用户画像、普通业务通知邮件、员工内部账号（不含高权限）、部门级汇总报表。
3 级敏感 / 高敏企业核心竞争力受损（商业秘密），或损害个人隐私权益。姓名 / 工作单位等普通个人信息、客户跟进记录、渠道成本与结算单、API 密钥。
4 级极敏感严重财产损失、名誉受损，或引发法律诉讼。手机号、身份证、精准定位、支付账号、购买记录；未公开的重大营销战略；千万级客户底层总池。

两个定级对象必须分清：资源（仪表板 / 报表）只有一个级别，表示它自身有多敏感； 审批流上设的是门槛，表示「从哪一级起需要它来审」。前者是等值，后者是区间。

10.2 管控方式：门槛（当前级别及以上）

审批流上的风险级别是下限，语义为「管控 ≥ 该级别 的数据」，而不是「只管控正好等于该级别的数据」。 设为 3 级 时，3 级与 4 级的仪表板下载都要走这条流程，1、2 级不受它约束。 所以这条流程的读法不是「3 级数据的审批」，而是「3 级及以上数据的审批」。

审批流门槛需要走这条流程不需要走
≥1 级 公开 / 低敏1、2、3、4 级（全量）无 —— 与改造前「所有下载都审批」等价
≥2 级 内部 / 中敏2、3、4 级1 级
≥3 级 敏感 / 高敏3、4 级1、2 级
≥4 级 极敏感4 级1、2、3 级

为什么是「及以上」而不是「等于」：① 报表被重新定级（2 级上调到 3 级）时会自动落进原本管 3 级的流程，不会因为「没有正好等于 3 级的流程」而漏审——门槛是单调的，级别往上调只会更严；② 与等保、密级、DLP 的通行表述一致，管理员不必二次理解；③ 若按「等于」实现，4 个级别要配 4 条几乎相同的流程，维护成本翻倍、且很容易配漏一级。

必须让管理员看见的副作用：门槛越高，管控范围越小。把一条流程从 3 级改成 4 级，意味着 3 级数据的下载也不再经过它——这是放宽，配置侧保存前需要二次确认；反过来从 4 级改成 3 级是收紧，直接生效并写日志即可。

10.3 资源级别从哪来

判定比较的是资源自己的级别。仪表板级别现在显式可见可维护，且有两个入口写同一字段： ① 新建时由系统落默认 1 级（保存弹窗只展示、不可改，见 5.5），随仪表板保存落库；改级由管理员在「风险控制」完成； ② 管理员在系统管理 → 风险控制列表里行内修正（见 5.7），单条即时生效。 两者都落到 dashboard.risk_level，它是下载判定唯一读取的字段；谁最后改以谁为准，靠变更记录追溯。

平台「数据分级」的结果（字段级密级向数据集聚合、取最高）不再直接充当仪表板级别，而是作为定级时的参考： 两者不一致时以业务在弹窗里的选择为准。理由是一张只引用了脱敏数据的看板，不应被上游密级一路拖到 4 级、审到没人愿意用； 反过来，把高敏数据包进低级别看板属于定级错误，用治理清单核对而不是用系统暗改（见 Q-08）。

仪表板尚未定级（存量数据、从未走过一次保存）时按 4 级 兜底，与该资源"改造前所有下载都要审批"的 现状对齐，避免上线即静默放行。这类资源进入治理清单，由 owner 在下次保存时确认。

10.4 下载时的判定

沿用现有下载审批链路，只在「选哪条流程」之前多一步按门槛过滤：

// 1. 取仪表板自身级别（新建默认 1 级，仅管理员在风险控制可改）；存量未定级按 4 级兜底
level = viz.riskLevel ?? 4

// 2. 保留启用中的下载类流程，且门槛不高于资源级别
//    存量流程未设置门槛 → 按 ≥1 级处理，行为与改造前一致
candidates = enabledDownloadFlows.filter(f => level >= (f.riskLevel ?? 1))

// 3. 没有候选 → 免审；有多条 → 按优先级取第一条
if (candidates.isEmpty) return 直接下载
flow = candidates.sortBy(priority).first()
return 进入审批(flow)

门槛只决定「要不要审」，不改变被命中流程自己的审批级数与审批人；多条同时命中时如何取舍见 Q-05。

  • 本期交付：风险控制场景——单条下拉改级、勾选后批量设级、按标签筛选、下载审批两态展示（5.7）。
  • 本期不做：流程配置侧的改造（流程列表新增「风险级别」列、新建/编辑流程设置门槛、按门槛筛选、放宽二次确认、免审区间提示条）。这些规则沿用 10.2–10.4 的口径，待配置侧排期时再出原型。
  • 因此的口径简化：风险控制列表的「下载审批」列按现状门槛呈现——1 级免审批、2–4 级需审批（现状启用流程最低门槛 ≥2 级）。接入配置侧能力后，该列随门槛自动变化，原型中的取值不再是常量。

Q-01是否需要"系统内置标签"（如"默认主题"），内置项不可删除？本期不做内置语义易与业务主题混淆，建议先观察真实使用情况。
Q-02标签是否需要按组织/空间隔离，而非租户级全局？租户级全局与现有目录的权限模型保持一致，降低实现复杂度。
Q-03是否需要"标签使用排行"或"未打标仪表板"治理视图？下期属于数据治理范畴，依赖标签使用数据积累。
Q-04批量打标（在列表勾选多个仪表板统一打标）是否纳入本期？下期当前仪表板列表无批量操作能力，需先补齐基础批量框架。
Q-05多条启用的下载流程同时命中时（如门槛 ≥2 与 ≥4），如何取舍：按优先级取第一条 / 逐级累计 / 只取最高门槛？取优先级第一条逐级累计会把下载链路越拉越长；只取最高门槛会让低门槛流程形同虚设。本文按「优先级第一条」写；若客户要求叠加审批，需改为串行多条并重新定义超时与撤回。
Q-06存量流程是否统一回填一个默认门槛？不回填默认值等于替业务做定级判断，容易失真。建议保留「未设置」并给出待办清单，由各流程负责人逐个确认；判定上按 ≥1 级兜底，行为与改造前一致。
Q-07资源（仪表板）级别从哪来——客户环境是否已启用数据分级？若尚未启用，本期是否要补一个仪表板级的手工标注入口？本期已补本期在保存弹窗补上仪表板级手工定级（默认 1 级），因此不再依赖数据分级覆盖率才能开门槛管控；平台分级结果降级为定级时的参考。存量未定级资源如何处置见 Q-08。
Q-08存量仪表板（未定级）如何处理：上线时统一回填 1 级，还是保留「未设置」按 4 级兜底？保留未设置回填 1 级等于替业务做定级，且会让存量仪表板静默退出门槛 ≥2 的流程，上线即放开一批下载；保留未设置则维持改造前的全量审批，由 owner 下次保存时确认。代价是短期审批量偏高，需配合治理清单推进。另：弹窗是否要给出「引用数据最高级」的建议值，一并确认。
Q-09风险控制列表已支持批量改级，是否还需要「改级双人复核」？批量已做；复核待定批量按「勾选 → 选等级 → 一次确认」落地，含降级时整批确认、单次上限 200 条（BR-12 / BR-14）。双人复核未做：它会让「纠偏」比「定级」还重，且当前改级已有变更记录可追溯。建议先用批量 + 变更记录观察实际放宽频次，再决定是否对「一次性降级超过 N 个」加二级审批。另：谁有权改他人看板的等级（全局管理员 / 目录管理员）仍需明确。

配套原型：点击右上角「交互原型」查看 5 个场景的可点击高保真原型，按功能分为三组——报表标签管理（标签管理、保存时打标、详情页改标签）、下载报表风险控制（风险控制：列表内单条下拉改级、勾选后批量设级、可按标签筛选）、仪表板提示信息（提示信息管理：新建/编辑提示语、按触发时机与状态筛选、启用停用即时生效）。场景栏按大类 + 子场景两级组织：左侧是只列功能大类的下拉（选中项显示大类名与场景条数），右侧只列当前大类下的子场景，组内序号各自从 1 开始；切换大类后默认回到该大类上次看的场景。下钻页（如仪表板列表）不占场景位。标签管理里的「关联仪表板」数字可下钻到仪表板列表页。

系统管理 · 风险控制
  1. 入口：系统管理 → 风险控制，与「仪表板标签」并列。只有系统管理员可改；业务方仍在自己保存仪表板时定级，两个入口写的是同一个字段。

  3. 改等级不用进详情：点等级胶囊选 1–4 级，选中即生效，右侧「下载审批」同步刷新——管理员能当场看到这次改动的后果。
  4. 支持批量：行首勾选（表头全选只作用于当前筛选结果）后，表格上方常驻批量条（两端分布）：左「已选 N 项」，右「批量设为」+ 目标等级 + 应用（未勾选时「应用」置灰）；再点行首或表头复选框即可取消勾选。切换筛选自动清空已选。单次上限 200 个。
  5. 筛选区第三项是标签多选：展开后按标签勾选（多选为「任一命中」），按钮上回显标签名或「已选 N 个标签」，可与名称、等级叠加过滤。
  6. 降级要二次确认：4 级改 1 级等于放宽，弹窗写明「降为 1 级后下载不再需要审批」，确认后才生效；批量中含降级时合并成一次确认，写明 N 个里几个是降级。
  7. 顶部四个数字是各等级仪表板数量，点卡片即按该等级筛选；与流程表单里的「管控范围」用同一份分级统计。
边界：这里改的是资源自身级别，不碰流程门槛；历史审批记录里的两项快照不回溯。

仪表板标签

在现有 BI 产品的仪表板上引入「标签」这一轻量元数据能力：由系统管理员统一维护标签字典， 业务用户在保存仪表板时为其打上若干标签，从而支撑仪表板的归类、检索与治理。

另：仪表板保存时新增「风险级别」（默认 1 级），流程配置新增风险级别门槛（1–4 级，含本级及以上）； 下载审批按「资源级别 ≥ 门槛」判定，详见第 10 章。

01需求背景与目标

当前仪表板仅通过「目录 / 文件夹」做单一层级的归置，一个仪表板只能落在一个目录下。 但业务方的实际诉求是多维归类：同一张经营分析看板，既属于「财务」主题，也服务于「经营分析」主题。 目录无法表达这种多归属关系，导致：

  • 仪表板资产量大后，用户只能靠名称搜索，找不到「某个主题下都有哪些看板」；
  • 数据治理时无法按业务主题盘点资产，资产地图缺失；
  • 新增看板时无法快速复用同主题的历史看板，重复建设。

本需求引入「标签」，作为与目录并行的第二套归类维度：目录解决「放在哪里」（唯一归属、有层级）， 标签解决「是什么主题」（多归属、扁平、可交叉）。

02名词定义与设计取舍

术语定义
标签用于标识仪表板所属业务主题（如财务、供应链、人力）的扁平化元数据，全局唯一，由管理员统一维护。
标签字典系统管理模块中维护的全部标签集合，是打标时的可选范围来源。用户不可在打标时随意创建"私有标签"以外的字典项。
绑定关系仪表板与标签的多对多关联记录。一个仪表板可绑定多个标签，一个标签可被多个仪表板绑定。
关联数某标签当前被多少个仪表板绑定，用于删除前的风险提示。

为什么用"多对多"而不是"单选标签"

若做成单选，用户必须为看板强行指定唯一主题，跨主题看板会被迫二选一，长期必然出现"选哪个都别扭"的问题，且后期改造成本高。 多对多虽增加了一次选择的复杂度，但通过数量上限（10 个）+ 已选计数 + 可搜索选择即可控制，收益远大于成本。

03整体流程

1
管理员配置标签字典 系统管理 → 仪表板标签：新建、编辑、删除标签，维护全局可选范围。
2
用户在保存时打标 新建/编辑仪表板 → 保存弹窗 → 风险级别（1–4 级，默认 1 级）+ 标签（多选，可内联新建）。
3
标签在消费侧生效 仪表板列表展示标签、按标签筛选；详情页展示并可随时修改。

05功能详述

5.1 系统管理 · 仪表板标签（列表页）

入口：系统管理 → 仪表板标签。左侧导航中「系统管理」为二级菜单，「仪表板标签」与用户管理、角色权限并列。

区域内容与规则
页面标题区标题「仪表板标签」+ 一句话说明「统一维护仪表板的标签，供保存仪表板时选择」；右侧主按钮「新建标签」。
筛选区标签名称输入框（占位「请输入标签名称」）+「查询」「重置」；输入框支持回车查询。名称搜索为 contains 模糊匹配，忽略首尾空格。
列表列标签名称（主字段，加粗）｜关联仪表板（数字，可点击跳转到已筛选的仪表板列表）｜创建人｜创建时间｜更新时间｜操作。
操作列「编辑」「删除」两个文字按钮，固定右侧。删除为危险色。
排序默认按更新时间倒序；新建/编辑成功后该行回到首位并高亮 1.5s。
分页默认 20 条/页，展示总数；数据不足 1 页时仍展示总数文案，隐藏翻页按钮。
空状态无任何标签时展示插画 +「还没有标签」+「新建第一个标签」按钮；搜索无结果时展示「未找到匹配的标签」+「清空筛选」。

5.2 新建标签

点击「新建标签」弹出居中弹窗，宽度 440px，仅一个表单项。

  • 标签名称（必填）：单行输入框，maxlength = 20，右下角实时显示 n/20 计数。
  • 校验时机：输入时只做长度截断；失焦与提交时做唯一性校验，错误内联展示在输入框下方，不弹 toast。
  • 提交中按钮进入 loading 且禁用，防止重复提交；成功后关闭弹窗、toast「标签创建成功」、列表刷新。
  • 按 Esc 或点击遮罩关闭；若已输入内容，关闭前不做拦截（轻量表单，避免过度打扰）。

唯一性规则：全租户内标签名称唯一，比较时忽略首尾空格且不区分大小写（"财务"与"财务 "视为重复；"Finance"与"finance"视为重复）。

5.3 编辑标签

弹窗结构同新建，标题为「编辑标签」，名称预填当前值。顶部展示影响提示：「修改名称后，已关联的 N 个仪表板将同步展示新名称。」

保存时若名称未发生变化，则不发请求直接关闭；若变化，走同一套唯一性校验（排除自身 ID）。

5.4 删除标签

场景弹窗文案与交互
关联数为 0标题「删除标签」；正文「删除后不可恢复，确定删除标签「{name}」吗？」；按钮「取消 / 删除」。
关联数 > 0标题「删除标签」；正文「标签「{name}」已被 N 个仪表板使用，删除后这些仪表板将不再展示该标签，仪表板内容不受影响。」；按钮「取消 / 删除」。正文以警示色强调数量。

删除为软删除（记录标记 deleted=1），绑定关系同步失效。删除成功后列表移除该行、toast 提示，分页自动回退（当前页为空时跳转上一页）。

5.5 保存仪表板：风险级别与标签

在仪表板编辑态点击「保存」后弹出的保存弹窗中，新增「标签」配置区（非必填）。 编辑已有仪表板时，弹窗需回显该仪表板当前已绑定的标签。

本期在同一弹窗新增「风险级别」，位于「保存位置」之后、「标签」之前。它是仪表板自身的资源级别： 下载审批时与流程门槛比较（资源级别 ≥ 门槛才需要审批），与标签互不影响。

元素规则
控件形态四段单选，上行「n 级」、下行级别名（公开 / 低敏、内部 / 中敏、敏感 / 高敏、极敏感）。只有 4 个选项，平铺比下拉更容易一眼看清"我在哪一级"。
默认值默认选中 1 级，必填、不允许为空。默认取最低级别：新建看板多数是公开或内部数据，若默认最高级，"没细想"会直接变成"全量审批"。
影响提示控件下方一句话实时说明后果：「下载时将命中 k 条启用流程（门槛 ≤n 级）」，k 为 0 时改为「按当前生效的流程，下载无需审批」。数字取分级统计接口，不写死。
编辑回显编辑已有仪表板时回显当前级别；存量未定级的仪表板带出 1 级，并提示"原来未定级，按 4 级受控"（存量处置见 Q-08）。
提交与仪表板、标签同一次请求提交（riskLevel），不单独开接口，避免"级别存了、仪表板没存"。
展示位详情页标题后展示级别徽标，形如 2 级 · 内部——不带 ≥：资源侧表示自身级别，流程侧 ≥3 级 才是门槛，两种符号不得混用。

标签配置区（非必填，最多 10 个）：

元素规则
选择方式标签以可点击的 chip 平铺展示，点击切换选中；已选 chip 为品牌色描边+浅底+勾选图标。
已选计数区域右上角展示「已选 n/10」，n 随点击实时变化；达上限后未选中的 chip 置灰不可点，并 toast「最多选择 10 个标签」。
内联新建末尾提供「+ 新建标签」；点击展开一行输入框 + 「添加」按钮，添加成功后新标签立即以选中态出现在 chip 列表末尾，无需退出保存流程。
清空已选 > 0 时展示「清空」文字按钮，一键取消全部选中。
字典为空chip 区展示「暂无可用标签，先去创建」文案 +「新建标签」链接，仍可直接在本弹窗内创建。
提交与仪表板保存同一次请求提交（标签作为 tagIds[] 字段），避免"标签存了但仪表板没存"的不一致。

5.6 仪表板列表与详情展示

  • 列表列：新增「标签」列，位于「所属目录」之后。最多展示 3 个标签，超出显示 +N，hover 浮层展示全部标签名称。
  • 筛选：筛选区新增「标签」多选下拉，支持搜索与「清空」；多个标签之间为 或 关系（命中任一即展示），结果与目录筛选为 与 关系。
  • 无标签：展示「—」，不占位、不显示"未打标"文案，避免列表噪音。
  • 目录树：左侧目录树顶部固定「仪表板概览」，默认选中，以列表形式展示全部仪表板（含标签列）；点击具体目录后列表按目录过滤，页面标题与数量随之切换，概览项始终置顶。
  • 详情页：标题下方展示全部标签 chip；右侧「编辑标签」入口，点击弹出与保存弹窗一致的标签选择弹窗，独立提交、即时生效，无需进入编辑态。
  • 风险级别：详情页标题后展示级别徽标（如 2 级 · 内部），修改入口在「保存」弹窗内；与标签各自独立，互不覆盖。

06业务规则

编号规则描述
BR-01名称唯一标签名称在租户内全局唯一，忽略首尾空格、不区分大小写。
BR-02名称格式1–20 个字符；允许中文、英文字母、数字、下划线、中划线、空格（非首尾）；禁止 / \ : * ? " < > | 等特殊字符与 emoji。
BR-03绑定上限单个仪表板最多绑定 10 个标签，最少 0 个（标签非必填）。
BR-04改名同步标签改名后，所有已绑定仪表板同步展示新名称（通过 tagId 关联，不做名称冗余）。
BR-05删除解绑删除标签时级联解除全部绑定关系；仪表板本身、目录归属、权限均不受影响。
BR-06软删除标签删除为软删除，保留 ID 以防历史操作日志/审计记录断链；已删除标签不可被再次绑定。
BR-07原子提交仪表板保存时，基础信息与标签绑定在同一事务内提交，任一失败则整体回滚。
BR-08权限隔离无「仪表板标签管理」权限的用户，系统管理菜单中不展示该项；无仪表板编辑权限的用户，保存弹窗中标签区只读展示。
BR-09排序稳定列表默认按 update_time DESC 排序，同一秒内按 id DESC 兜底，保证分页稳定。
BR-10租户隔离标签数据按租户隔离，跨租户不可见、不可复用。

07数据结构与接口

7.1 表设计

-- 标签字典
CREATE TABLE dashboard_tag (
  id           BIGINT       PRIMARY KEY AUTO_INCREMENT,
  tenant_id    VARCHAR(64)  NOT NULL,
  name         VARCHAR(20)  NOT NULL COMMENT '标签名称，1-20字符',
  rel_count    INT          NOT NULL DEFAULT 0 COMMENT '关联仪表板数（冗余，便于列表展示）',
  creator_id   VARCHAR(64)  NOT NULL,
  creator_name VARCHAR(64)  NOT NULL,
  create_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted   TINYINT      NOT NULL DEFAULT 0,
  UNIQUE KEY uk_tenant_name (tenant_id, name, is_deleted),
  KEY idx_update (tenant_id, update_time)
) COMMENT '仪表板标签';

-- 仪表板 × 标签 多对多
CREATE TABLE dashboard_tag_rel (
  id           BIGINT      PRIMARY KEY AUTO_INCREMENT,
  tenant_id    VARCHAR(64) NOT NULL,
  dashboard_id VARCHAR(64) NOT NULL,
  tag_id       BIGINT      NOT NULL,
  create_time  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_dash_tag (dashboard_id, tag_id),
  KEY idx_tag (tag_id)
) COMMENT '仪表板标签绑定关系';

说明：rel_count 为冗余字段，绑定/解绑时同步维护，避免列表页对关联表做 count 聚合；对账任务每日校准一次。 唯一索引包含 is_deleted，以支持软删除后同名标签可重新创建。

08边界与异常

场景处理策略
保存仪表板时，所选标签已被他人删除提交前不做实时校验；失败后返回 TAG_NOT_FOUND，弹窗保持打开，自动刷新标签选项并移除失效项，提示用户重新确认后再次保存。
两人同时新建同名标签以数据库唯一索引兜底，后提交方返回 DUP_TAG_NAME，前端内联提示。
标签名称前后有空格提交前 trim；仅空格视为空值，触发必填提示。
已选满 10 个后继续点击未选中的 chip 呈禁用态（cursor:not-allowed、透明度 45%），点击 toast 提示上限。
标签字典为空时保存仪表板标签区不阻塞保存；展示「暂无可用标签，先去创建」并提供内联新建入口。
删除当前页最后一条刷新后若当前页无数据且页码 > 1，自动回退一页。
无标签权限的用户访问打标接口返回 403，前端 toast「暂无权限操作标签」，不暴露标签字典内容。
关联数展示与实际瞬时不一致允许短暂误差；点击关联数跳转时以实时查询结果为准，不以冗余字段作为跳转依据。

10审批流风险级别

审批流目前只表达「谁审、审几级」，不表达「这条流程卡的是什么级别的数据」。 管理员在流程配置里看到「二级角色部门审批 / 2 级」，无法判断它管的是公开的促销素材，还是含手机号的客户明细； 安全与合规同事做审计时，也只能逐个流程点进去看。 本章为审批流增加风险级别：新建或编辑流程时标注 1–4 级，表示「本级及以上」都受这条流程管控，列表直接展示，并支持按级别筛选与审计。

与标签功能的关系：两者互不依赖、可分别上线。标签解决「仪表板是什么主题」，风险级别解决「审批流管多敏感的数据」。本文档第 1–9 章为标签，第 10 章为风险级别。

10.1 分级口径

参照 GB/T 43697-2024《数据安全技术 数据分类分级规则》的纵向划分：核心数据、重要数据、一般数据， 其中一般数据内部可再细分。BI 平台承载的是企业经营分析数据，绝大多数落在「一般数据」区间， 因此本功能不判定核心 / 重要数据，只把「一般数据」内部再细分为 4 级。 若客户场景确实涉及核心 / 重要数据（如服务国防、能源、大规模高精度地理数据）， 按客户侧定级结论单独约定，不走本功能的四级模型。

级别名称判定口径（泄露后的影响）典型数据（经营 / 营销场景）
1 级公开 / 低敏无影响或影响极微弱，可对外披露。商品公开价格、官网促销图文、公开的用户评价、已对外发布的经营月报。
2 级内部 / 中敏造成轻微竞争劣势，或对个人造成轻微困扰。匿名化用户画像、普通业务通知邮件、员工内部账号（不含高权限）、部门级汇总报表。
3 级敏感 / 高敏企业核心竞争力受损（商业秘密），或损害个人隐私权益。姓名 / 工作单位等普通个人信息、客户跟进记录、渠道成本与结算单、API 密钥。
4 级极敏感严重财产损失、名誉受损，或引发法律诉讼。手机号、身份证、精准定位、支付账号、购买记录；未公开的重大营销战略；千万级客户底层总池。

两个定级对象必须分清：资源（仪表板 / 报表）只有一个级别，表示它自身有多敏感； 审批流上设的是门槛，表示「从哪一级起需要它来审」。前者是等值，后者是区间。

10.2 管控方式：门槛（当前级别及以上）

审批流上的风险级别是下限，语义为「管控 ≥ 该级别 的数据」，而不是「只管控正好等于该级别的数据」。 设为 3 级 时，3 级与 4 级的仪表板下载都要走这条流程，1、2 级不受它约束。 所以这条流程的读法不是「3 级数据的审批」，而是「3 级及以上数据的审批」。

审批流门槛需要走这条流程不需要走
≥1 级 公开 / 低敏1、2、3、4 级（全量）无 —— 与改造前「所有下载都审批」等价
≥2 级 内部 / 中敏2、3、4 级1 级
≥3 级 敏感 / 高敏3、4 级1、2 级
≥4 级 极敏感4 级1、2、3 级

为什么是「及以上」而不是「等于」：① 报表被重新定级（2 级上调到 3 级）时会自动落进原本管 3 级的流程，不会因为「没有正好等于 3 级的流程」而漏审——门槛是单调的，级别往上调只会更严；② 与等保、密级、DLP 的通行表述一致，管理员不必二次理解；③ 若按「等于」实现，4 个级别要配 4 条几乎相同的流程，维护成本翻倍、且很容易配漏一级。

必须让管理员看见的副作用：门槛越高，管控范围越小。把一条流程从 3 级改成 4 级，意味着 3 级数据的下载也不再经过它——这是放宽，保存前要二次确认（BR-10-07）；反过来从 4 级改成 3 级是收紧，直接生效并写日志即可。

10.3 资源级别从哪来

判定比较的是资源自己的级别。仪表板级别现在显式可见可维护：在保存仪表板的弹窗里填写 （默认 1 级，见 5.5），随仪表板保存落库，是下载判定唯一读取的字段。

平台「数据分级」的结果（字段级密级向数据集聚合、取最高）不再直接充当仪表板级别，而是作为定级时的参考： 两者不一致时以业务在弹窗里的选择为准。理由是一张只引用了脱敏数据的看板，不应被上游密级一路拖到 4 级、审到没人愿意用； 反过来，把高敏数据包进低级别看板属于定级错误，用治理清单核对而不是用系统暗改（见 Q-08）。

仪表板尚未定级（存量数据、从未走过一次保存）时按 4 级 兜底，与该资源"改造前所有下载都要审批"的 现状对齐，避免上线即静默放行。这类资源进入治理清单，由 owner 在下次保存时确认。

10.4 下载时的判定

沿用现有下载审批链路，只在「选哪条流程」之前多一步按门槛过滤：

// 1. 取仪表板自身级别（保存弹窗设置，默认 1 级）；存量未定级按 4 级兜底
level = viz.riskLevel ?? 4

// 2. 保留启用中的下载类流程，且门槛不高于资源级别
//    存量流程未设置门槛 → 按 ≥1 级处理，行为与改造前一致
candidates = enabledDownloadFlows.filter(f => level >= (f.riskLevel ?? 1))

// 3. 没有候选 → 免审；有多条 → 按优先级取第一条
if (candidates.isEmpty) return 直接下载
flow = candidates.sortBy(priority).first()
return 进入审批(flow)

门槛只决定「要不要审」，不改变被命中流程自己的审批级数与审批人；多条同时命中时如何取舍见 Q-05。

为什么是整页而不是弹窗：审批级数会动态增删节点卡，4–5 级时表单高度接近两屏；弹窗内滚动会让「基础信息」和「审批节点」脱节，而门槛恰恰要和审批级数、管控范围对着看（≥4 级配 1 级审批是重点提示项）。整页还便于把某条流程的地址直接发给审计同事定位。

为什么不给默认值：只要有默认值，管理员就会一路回车把定级变成走过场，最终所有流程都是同一个门槛，字段也就失去意义。必填带来的那一次停顿，正是让定级被真正思考的成本。

10.9 边界与异常

场景处理
资源 3 级，流程门槛 ≥3命中，进入审批；阈值相等即命中（>= 而非 >），这是「本级及以上」的核心。
资源 2 级，流程门槛 ≥3不命中，直接下载；若此时没有其他更低门槛的流程，即形成免审区间，列表顶部的橙色条必须能反映出来。
存量流程未设置门槛判定按 ≥1 级（全量），与改造前一致；徽标显示「未设置」，编辑时必须补选。
存量仪表板未定级按 4 级兜底，所有启用流程都会命中；进入治理清单，下次保存时弹窗提示「原来未定级，按 4 级受控」。用户选定后即按新值判定，下调属放宽，见 Q-08。
新建仪表板不选级别直接保存不允许：字段必填，默认已选 1 级，因此"不选"实际等于"用默认值"；接口收到空值也按 1 写入，不落 NULL。
门槛上调但未确认前端拦截保存；直接调接口返回 RISK_SCOPE_NOT_ACKED，库中门槛保持原值。
所有启用流程门槛都 ≥21 级数据免审。列表顶部出现橙色条「1 级数据当前无审批流程覆盖」，不阻断保存。
资源被降级（3 级 → 2 级）实时生效，下次下载不再命中 ≥3 的流程；审计靠资源的级别变更记录追溯，审批记录中的 resource_risk_level 不变。
同一资源同时命中 ≥2 与 ≥4 两条流程按优先级取第一条，不逐级累计（BR-10-08、Q-05）。
旧版本前端提交编辑，未携带 riskLevel后端保留原值，不写 NULL；日志中不产生变更记录。
字典 / 统计接口不可用徽标降级为「文本 + 灰色」，不阻塞列表渲染；表单内提示「分级说明加载失败」，仍允许按数字选择，「管控范围」一行隐藏而不是显示 0。
同一租户内两条流程门槛不同但名称相近不合并、不校验；门槛是流程自身属性，不做跨流程一致性约束。

  2. 风险级别是门槛：下拉写「≥3 级 · 敏感 / 高敏」，含义是 3 级和4 级都受控。选完立刻在下一行给出「管控范围」。
  3. 管控范围=刻度条 + 一句话：「计入 3–4 级，约 12 个仪表板；1–2 级数据下载不触发本条流程」。门槛以上的格子点亮，以下的置灰，不用心算。
